无需编辑配置文件，即可在 WebUI 中集中管理人格、回复模型、记忆隔离、插件权限、人格计划以及第三方插件兼容功能。

## 功能特色

- **按用户分配人格**：私聊用户、群聊和群成员可以使用不同的 AstrBot 人格。
- **自动选择人格**：根据当前消息从候选人格中自动选择，并支持独立选择模型。
- **独立回复模型**：规则和候选人格均可指定回复 Provider，不修改 AstrBot 全局模型配置。
- **双重记忆隔离**：分别控制 AstrBot 对话历史与 LivingMemory 长期记忆。
- **插件权限控制**：支持全部允许、白名单和黑名单，并可让群成员继承群聊设置。
- **用户与群聊管控**：提供用户封禁、群成员访问名单和群策略管理员。
- **人格计划**：按每天、每周或随机间隔自动切换目标人格。
- **会话导入**：发现已有私聊和群聊会话，快速生成默认策略。
- **第三方兼容适配**：支持 Private Companion、LivingMemory、Proactive Chat、Life Scheduler、Meme Manager、Smart ImageChat Hub 等插件。
- **原生 WebUI**：使用 AstrBot Plugin Pages，不开放额外管理端口。
- **冲突保护**：通过配置修订号阻止多个页面互相覆盖策略。
- **低开销匹配**：缓存插件目录，避免大群消息复制完整成员表，状态写盘异步合并。

## 安装与使用

### 环境要求

- AstrBot `>= 4.24.2, < 5`
- Python 环境满足当前 AstrBot 版本要求
- Python 依赖：`PyYAML >= 6.0`

### 安装步骤

1. 将插件目录放入 AstrBot 的插件目录：

   ```text
   data/plugins/astrbot_plugin_user_policy/
   ```

2. 安装依赖：

   ```bash
   pip install -r requirements.txt
   ```

3. 在 AstrBot WebUI 中重新加载插件。
4. 打开“插件”页面，进入“多人格管理”。
5. 添加私聊用户或群聊规则，并选择对应人格。

> [!TIP]
> 安装前已经存在的会话不会被删除。首次生成空策略时会自动导入已有会话；之后更新或重载插件不会再次自动导入。需要重新扫描时，可在私聊用户或群聊页面点击“导入已有会话”。被你删除过的导入项会被记入忽略列表，除非手动重新添加，否则不会再次导入回来。
> 导入会话会保存为 `平台:用户ID` 或 `平台:群ID`，例如 `default:<用户ID>`，用于区分多个机器人；手动添加裸 ID 仍可作为通用规则使用。
> 升级到 `3.4.13` 时，旧配置中的顶层裸用户 ID、群 ID、计划目标和导入忽略项会一次性迁移为 `default:ID`；群内成员 ID 保持不变。

## WebUI 控制台

### 私聊用户

管理指定用户的：

- 使用状态与封禁状态
- 固定人格或自动人格
- 回复模型
- AstrBot 对话记忆隔离
- LivingMemory 人格记忆隔离
- Private Companion 私聊主动对话权限
- 自行切换人格权限
- 第三方插件权限

添加用户时填写用户 ID，选择允许或禁止使用，再按需配置人格、模型、两类记忆隔离和插件权限。列表中的每个用户都可以直接编辑或删除。

### 群聊管理

管理每个群聊的：

- 群默认人格与回复模型
- 自动人格候选范围
- 群聊记忆隔离
- 成员允许名单或禁止名单
- 群策略管理员
- 群聊插件权限
- 群成员专属人格和覆盖规则

成员访问名单支持每行一个用户 ID，也支持中文或英文逗号分隔。群成员可以分别选择继承群聊设置、单独开启或单独关闭记忆隔离与插件权限。

策略匹配优先级为：

```text
群成员专属规则 > 群聊默认规则 > 私聊用户回退规则 > AstrBot 会话默认
```

### 人格计划

为私聊用户、群默认人格或群成员创建自动切换计划：

| 模式 | 说明 |
| :--- | :--- |
| 每天指定时间 | 每天在固定时间切换到指定人格 |
| 每周安排 | 为不同星期分别指定人格 |
| 随机间隔 | 每隔一段时间从候选人格中随机选择 |

计划只修改策略中的人格设置，不会主动发送消息，也不会启动第三方插件任务。

### 兼容状态

兼容状态页会显示：

- 插件是否安装
- 插件是否启用
- 运行时适配是否成功
- 接口是否暂不兼容
- 是否已安全回退为原插件行为

“低冲突设计”是固定的职责边界说明，不是可切换状态。

插件选择器会保留已在规则中使用但后来被卸载的插件，并标记为“当前未安装”。重新安装同名插件后，原权限规则会自动恢复关联。

## 人格与模型

### 固定人格

直接从 AstrBot 的“人格设定”中选择。命中规则后，本插件只对当前请求应用该人格，不修改其他会话的全局人格。

### 自动人格

自动人格会根据最新消息，从管理员配置的候选人格中选择一个最终人格。每条规则可以设置：

- 候选人格范围
- 人格选择模型
- 整体场景说明
- 每个人格的描述与适用场景
- 每个人格独立的回复模型

> [!NOTE]
> 自动人格每次回复前需要额外调用一次人格选择模型，因此会增加一次模型请求的延迟。固定人格没有这次调用。

## 记忆隔离

本插件提供两类互相独立的隔离设置。

### AstrBot 对话记忆

开启后，不同人格使用独立的 AstrBot 对话历史：

- 首次启用时保留当前人格已有上下文
- 首次切换到新人格时使用新的历史
- 切回原人格后恢复该人格原有历史
- 群成员专属人格不会覆盖全群当前对话

### LivingMemory 长期记忆

当检测到 LivingMemory 且运行时适配成功时：

- 开启隔离：召回与写入使用最终人格 ID
- 关闭隔离：使用共享长期记忆
- 未配置策略：保留 LivingMemory 原行为

LivingMemory 不提供全局隔离开关，只按私聊用户、群聊和群成员规则工作。本插件不会复制、合并或迁移 LivingMemory 的历史数据库。

## 人格计划

人格计划使用 AstrBot 所在系统的本地时区，并持久化以下信息：

- 计划配置
- 下次执行时间
- 上次执行结果
- 随机模式上一次选择

随机切换至少需要两个人格，间隔范围为 5 至 10080 分钟。插件重启或重新加载后会恢复尚未执行的计划。

### Private Companion 主动对话

Private Companion 的私聊主动发送必须同时满足：

1. Private Companion 原始判断允许。
2. 多人格管理全局总闸允许。
3. 该私聊用户的逐用户分闸允许。
4. 用户未被本插件封禁。
5. 当前插件权限允许 Private Companion。

全局总闸关闭时，逐用户分闸不能单独放行。逐用户开启只表示允许进入原插件判断，不会强制覆盖 Private Companion 自身的关系、陪伴状态、用户关闭、免打扰、频率或每日上限。

当前适配目标基于 Private Companion `3.4.2`。若接口变化，兼容状态页会显示“版本暂不兼容”，并安全回退为 Private Companion 自身行为。群聊插话等群功能不受此开关控制。

Private Companion 的图片识别由其自身直接调用视觉提供商。原插件默认会先等待图片防抖，再等待视觉任务；主回复为空时还可能再次识图并调用兜底模型。兼容卡片默认启用快速识图保护：

- 图片防抖上限默认为 `1.5` 秒。
- 单次视觉任务上限默认为 `15` 秒。
- 同一图片超时后 30 秒内不再次发起完整识图。
- 识图完成后的内部延迟事件沿用当前人格，不再额外调用人格选择模型。

这些设置不改变视觉 Provider，也不保证慢速主回复模型一定在 30 秒内完成。用户可以在兼容卡片关闭快速保护，或将两个等待上限调整为适合当前模型的值。

### 兼容原则与边界

本插件只在必要的运行入口附加可回退适配，不读取其他插件的私有配置文件，也不会修改其数据库、令牌或全局启用状态。

- 插件权限只收窄当前入站消息的处理器、后续钩子和可识别所属插件的 LLM 工具。
- 后台定时任务和其他插件直接发起的模型调用不会因缺少入站用户身份而被拦截。
- 唯一主动任务例外是用户明确配置的 Private Companion 私聊主动对话门控。
- 人格计划只更新本插件策略，不发送消息，也不调用第三方插件任务。
- AstrBot 内置插件和多人格管理自身不会进入可禁用列表。
- 第三方插件接口变化时停止包装并安全回退，不强制继续运行不兼容代码。

具体适配行为：

- **Meme Manager（暂停维护）**：当前仅保留既有适配和安全回退，不再继续扩展新能力。聊天运行期间按“最终命中的人格”自动临时切换图库；原插件 WebUI 继续管理默认图库。独立图库保存在本插件数据目录中。管理人格图库时可上传单张图片或 ZIP；ZIP 根目录图片进入当前分类，一级文件夹会作为分类批量导入。单图上限 10 MB，单个 ZIP 上限 50 MB，单次最多 500 张且解压后图片总量不超过 100 MB。只编辑命名图库不会自动生效，还需要在“人格使用的图库”里把对应人格映射到该命名图库。未映射、未命中人格或第三方指令缺少事件上下文时，会安全回退到 Meme Manager 真实默认库。
- **Smart ImageChat Hub**：适配目标为 `2.8.3`。管理界面会通过原插件候选入口读取 Smart ImageChat Hub 原图库，以只读方式展示图片和最终检索标签，并可复制为独立人格图库；不会修改原索引。启用后可创建、重命名和复制独立人格图库，并把人格映射到指定图库；支持图片或 ZIP 上传、按内容哈希去重、集中标签编辑、公用特征标签快捷勾选、把标签多选套用到含有相同图片的其他图库、缓冲池多选复制/移动/删除和 ZIP 备份。复制图库会生成独立标签副本，后续修改互不影响。上传时会先生成 Smart 风格的文件名基础标签，图片可立即参与检索；需要准确语义时可在图片卡片点击“智能打标”，调用 Smart 的视觉模型重新生成标签。共享池图片会按需镜像到 Smart ImageChat Hub 数据目录下的专用子目录，但不会写入其原索引。未映射人格、空图库、缺少可靠人格上下文或接口异常时回退原全局图库。
- **Proactive Chat**：私聊固定人格直接读取当前用户策略，自动人格按会话读取最后有效选择；可附加隔离对话历史、主动消息要求和当日日程。
- **Life Scheduler**：适配 [muyouzhi6/astrbot_plugin_life_scheduler](https://github.com/muyouzhi6/astrbot_plugin_life_scheduler)。映射人格使用本插件的命名日程库，未映射人格继续使用原插件全局日程；每个命名日程库都有独立创意池和每日记录，不会写入原始 `schedule_data.json`。创意池只影响新生成或重写的日程；当天已经生成过记录时会优先复用已有记录，需要重写或删除当天记录后才会看到新池效果。
- **DynamicPersona**：命中本插件固定或自动人格规则时以本插件结果为准；未配置策略的会话保留 DynamicPersona 行为。
- **Gitee AI Image**：仅在调用期间按“最终命中的人格”临时追加人格生图效果，完成后恢复原始消息。效果配置必须保存到对应人格；未命中人格、该人格未配置效果或兼容入口未包裹成功时，不会改写生图提示词。
- **QQ Group Daily Analysis**：用户主动命令应用插件权限，后台定时分析继续独立运行；其内部强制人格不会被覆盖。

## 插件权限

每条规则支持三种权限模式：

| 模式 | 说明 |
| :--- | :--- |
| 允许全部 | 当前用户或群聊可以使用所有已启用第三方插件 |
| 只允许选中 | 仅允许白名单中的插件 |
| 禁用选中 | 允许其他插件，但拒绝黑名单中的插件 |

群成员还可以选择“沿用群聊插件权限”。

权限会收窄当前入站消息的插件处理器、后续钩子和可识别所属插件的 LLM 工具。AstrBot 内置插件和本插件不会进入可禁用列表。

## 常见问题

### “已连接 · 配置修订 #32”是什么意思？

`32` 是策略数据的配置修订号，不是插件版本。每次成功保存策略后修订号都会递增，用于阻止旧页面覆盖其他页面刚保存的内容。

插件版本请查看插件信息中的 `3.5.3`。

### 为什么修改 AstrBot 配置默认人格后，回复还是旧人格？

AstrBot 的已有会话可能已经绑定了旧的 `conversation.persona_id`。这种情况下，AstrBot 会优先使用当前会话绑定人格，而不是新的全局默认人格，所以只改配置文件或重载插件不会改变这条会话。

处理顺序：

1. 发 `/当前人格` 查看“本插件策略”“AstrBot 当前会话绑定”和“AstrBot 全局默认”。
2. 如果当前仍命中本插件固定或自动人格规则，先在 WebUI 修改规则，或发 `/恢复人格` 清除个人覆盖。
3. 如果本插件已经显示“跟随 AstrBot 会话默认”，但“AstrBot 当前会话绑定”仍是旧人格，发 `/重置会话人格`。它会新建一个未绑定人格的当前会话，下一次回复就会重新跟随 AstrBot 全局默认人格。

### 为什么 C 人格可以切换，但 B 人格一直像 A？

如果早期版本在 A 会话里第一次创建 B 的隔离会话，B 可能复制了 A 的历史上下文。之后再切 B，就会继续进入这条旧的 B 隔离会话，看起来像仍在用 A。

新版不再把其他人格的历史复制进新固定人格会话。已有的旧绑定可以在当前私聊或群成员范围内执行：

```text
/重置人格记忆 B人格名称
```

下一次切到 B 时会创建干净的新会话。该命令只解除本插件的隔离会话绑定，不删除 AstrBot 历史数据库。

### “低冲突设计”什么时候会变成兼容状态？

不会。“低冲突设计”只是固定说明。每个第三方插件自己的卡片才会显示已启用、未安装、适配成功、暂不兼容或安全回退等状态。

### 插件会增加回复延迟吗？

固定人格和普通权限匹配开销很低。1000 名成员规则的匹配基准约为 `0.04 ms/条`。

可能产生明显额外延迟的是自动人格，因为它需要在正式回复前额外请求一次人格选择模型。可以改用固定人格，或为选择器配置更快的模型。

### 为什么允许了 Private Companion 主动对话却没有发送？

本插件的“允许”不会强制开启 Private Companion。请继续检查原插件的：

- 用户是否启用
- 是否手动关闭
- 免打扰时间
- 主动频率
- 每日发送上限
- 目标用户状态

### LivingMemory 卡片为什么没有总开关？

LivingMemory 隔离改为完全按规则控制。请在私聊用户、群聊或群成员表单中分别设置，避免一个全局开关意外覆盖所有用户。

### 第三方插件显示“版本暂不兼容”怎么办？

表示目标插件的运行时接口与当前适配器预期不一致。本插件会停止包装并保留目标插件自身行为，不会强行修改其配置或数据库。

## 数据与升级

运行数据保存在 AstrBot 官方插件数据目录：

```text
data/plugin_data/astrbot_plugin_user_policy/
├── policy.json
├── memory_bindings.json
├── schedule_state.json
├── auto_persona_state.json
└── meme_persona_libraries/
```

写入使用临时文件和原子替换。自动人格状态仅在实际变化时异步合并写盘，插件退出前会强制刷新。

### 旧版本迁移

- 首次升级且不存在 `policy.json` 时，会尝试从旧版 `data/config.yaml` 导入可转换规则。
- 旧文件不会被修改。
- 旧策略缺少记忆隔离字段时按开启处理。
- 如果旧版 LivingMemory 全局隔离开关为关闭，升级后会把现有用户、群聊和成员规则迁移为逐规则关闭。
